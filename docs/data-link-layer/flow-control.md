# 流量控制 Flow Control

## 為什麼需要流量控制

如果傳送端速度比接收端處理速度快，接收端的緩衝區會被塞爆，導致資料遺失。流量控制就是協調兩端速度的機制。

## Stop-and-Wait

傳送端送出一個框後就停下來，等接收端回覆確認 (ACK) 才送下一個框。

- 優點：簡單
- 缺點：效率差，尤其在傳輸延遲高的網路上，大部分時間都在「等」

## Sliding Window（滑動窗口）

允許傳送端在收到確認之前，連續送出多個框（窗口大小決定可以連送幾個）。

- 優點：大幅提升傳輸效率，不用每個框都等確認
- 常見延伸：Go-Back-N、Selective Repeat（處理框遺失或出錯時的重傳策略差異）
