# 錯誤偵測與更正

訊號在傳輸過程中可能因為雜訊、干擾而出錯。這一節介紹怎麼「發現」錯誤（錯誤偵測），甚至「修好」錯誤（錯誤更正）。

## Parity Bit（奇偶校驗）

在資料後面加一個位元，讓整組資料中 1 的個數符合奇數（奇校驗）或偶數（偶校驗）。

**範例（偶校驗）**：資料 `1011000`，1 的個數是 3（奇數），所以補一個 `1` 讓總數變偶數 → 傳送 `10110001`

- 優點：簡單
- 缺點：只能偵測**奇數個**位元錯誤，兩個位元同時出錯就抓不到

## CRC (Cyclic Redundancy Check)

CRC 用多項式除法的概念，在資料後面附加一段「餘數」當作檢查碼。

**範例**：資料 `1101011011`，生成多項式對應的位元序列 `10011`（4 位元的 CRC，多項式長度需為 5）

1. 在資料後面補 4 個 0：`11010110110000`
2. 用生成多項式 `10011` 對這串資料做**模二除法**（其實就是重複 XOR）：

```
11010110110000
10011
-----
01001110110000
 10011
 -----
 0000101110000
     10011
     -----
     000111 0000
        ...（持續 XOR 直到除完）
```

3. 最後剩下的餘數（假設算出來是 `1110`）就是 CRC 檢查碼，附加到原始資料後面送出：`11010110111110`
4. 接收端收到後，用同一個生成多項式做同樣的除法，如果餘數是 `0000` 代表沒有錯誤

- 優點：偵錯能力遠優於 parity bit，硬體實作（用 shift register）效率高
- 常見應用：乙太網路、USB、儲存裝置

## Hamming Code（漢明碼，可更正錯誤）

Parity bit 和 CRC 只能「偵測」錯誤，Hamming Code 可以直接「定位並修正」單一位元錯誤。

**核心概念**：在資料中插入多個校驗位元，每個校驗位元負責檢查資料中特定的一組位元（依照位置的二進位表示決定）。

**範例：4 位元資料 `1011` 編碼成 Hamming(7,4)**

1. 校驗位元放在 2 的冪次位置：位置 1, 2, 4 是校驗位元 (p1, p2, p4)，位置 3, 5, 6, 7 放資料位元 `d1 d2 d3 d4` = `1 0 1 1`

   | 位置 | 1 | 2 | 3 | 4 | 5 | 6 | 7 |
   |---|---|---|---|---|---|---|---|
   | 內容 | p1 | p2 | d1=1 | p4 | d2=0 | d3=1 | d4=1 |

2. 計算每個校驗位元（偶校驗，涵蓋位置的二進位表示中該 bit 為 1 的所有位置）：
   - p1 檢查位置 1,3,5,7 → 1,1,0,1 → 1 的個數是 3（奇數）→ p1 = 1（補成偶數）
   - p2 檢查位置 2,3,6,7 → p2,1,1,1 → 讓總數偶數 → p2 = 1
   - p4 檢查位置 4,5,6,7 → p4,0,1,1 → 讓總數偶數 → p4 = 0

3. 最終傳送：`1 1 1 0 0 1 1`（位置 1~7）

**接收端如何抓出錯誤位置**：重新計算 p1、p2、p4 的校驗結果，把結果組成二進位數字，這個數字就是出錯的位置（0 代表沒錯）。

## 三種方法比較

| 方法 | 能偵測 | 能更正 | 額外開銷 |
|---|---|---|---|
| Parity Bit | 奇數個位元錯誤 | 否 | 極低 |
| CRC | 多位元錯誤（能力視生成多項式而定）| 否（只能偵測）| 低-中 |
| Hamming Code | 可偵測到雙位元錯誤 | 可更正單位元錯誤 | 中 |
